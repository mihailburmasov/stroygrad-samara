# СТРОЙГРАД — сайт строительной компании (Самара)

Многостраничный корпоративный сайт: главная, каталог из 14 услуг (у каждой своя страница), страница для УК и ТСЖ, портфолио, «О компании», контакты, политика конфиденциальности и согласие на обработку ПДн (152-ФЗ), страница 404.

**Стек:** PHP 8 без сторонних библиотек и без базы данных. Контент лежит в `data/*.json`, сборщик (`app/lib`) делает из него готовые HTML-страницы, админка (`app/admin`) правит JSON и сразу пересобирает сайт. Посетитель получает обычный статический HTML — быстро, хорошо для поисковиков, сайт работает, даже если админка сломается. Шрифт Manrope хранится на сайте.

## Главное правило: один источник правды

- **Контент** (тексты, услуги, фото, отзывы) живёт в `data/` и `public_html/img` **на сервере**. Его правит клиент в админке. Поток: сервер → сюда (`deploy.php pull`).
- **Код** (шаблоны, стили, скрипты, ядро админки) живёт здесь, в git. Поток: отсюда → сервер (`deploy.php push`). Заливка кода **никогда не трогает** `data/`, фото и `storage/`.
- HTML-страницы — производные, руками их никто не правит: они пересобираются после каждого сохранения в админке и после каждой заливки кода.
- Перед правкой шаблонов или данных у себя — сначала `pull`, иначе можно работать со старой версией контента.

## Быстрый старт (на своём компьютере)

Нужен PHP 8.1+ с расширениями `gd` (с WebP), `mbstring`, `curl`, `ftp`, `exif`. Node.js — только для проверки ссылок (`npm run check`) и старых скриптов подготовки фото.

```bash
php app/bin/build.php                      # собрать сайт в dist/
php -S 127.0.0.1:8080 app/dev-router.php   # сайт http://127.0.0.1:8080, админка /admin/
php app/bin/admin-setup.php <пароль>       # создать вход в админку (один раз)
npm run check                              # ссылки, картинки, H1, title/description, микроразметка, sitemap
DRAFT=1 php app/bin/build.php              # с подсветкой неуточнённых данных {{УТОЧНИТЬ: …}}
```

Локальные настройки — `app/config.local.php` (в git не хранится): адрес `http://127.0.0.1:8080`, без подпапки, без секретного адреса входа. Настройки по умолчанию — `app/config.php`.

## Админка

Адрес входа: `https://домен/admin/<секретное-слово>` → пароль. Без секретного адреса любой адрес `/admin/...` отвечает обычной страницей 404 — для посторонних админки не существует.

Что умеет:
- **Страницы**: главная, каталог услуг, УК и ТСЖ, портфолио, о компании, контакты — все тексты, фон первого экрана, SEO-заголовок и описание.
- **Услуги**: правка всех блоков страницы, добавить новую (создаётся скрытой, пока не заполнена), скопировать, скрыть, поменять порядок в меню, удалить в корзину. Ссылки на удалённую услугу убираются со всего сайта сами.
- **Компания и контакты**: телефоны, почта, мессенджеры, реквизиты, слоганы — меняются на всём сайте сразу.
- **Отзывы**, **общие блоки**.
- **Фото**: загрузка перетаскиванием (браузер уменьшает крупные фото, сервер делает WebP 1280 и 640 px), подписи, папки, порядок, «не показывать в портфолио», удаление в корзину. Фото, которое где-то используется, удалить нельзя — админка скажет где.
- **Заявки**: все заявки с форм сайта.
- **История правок**: перед каждым сохранением прежняя версия откладывается; любую можно вернуть.
- **Корзина**: удалённые услуги и фото, без срока хранения.
- **Настройки**: куда слать заявки (почта, Telegram-бот), смена пароля.

Вошедший в админку видит на страницах сайта кнопку «✎ Редактировать страницу» — она ведёт прямо в нужный раздел.

Если сохранение ломает сборку (например, битая ссылка на фото), файлы возвращаются как были и админка показывает ошибку — сайт не ломается.

## Где что в коде

| Что | Где |
|---|---|
| Шаблоны страниц | `app/lib/pages.php` (страницы), `app/lib/render.php` (шапка, подвал, формы, оболочка), `app/lib/icons.php` |
| Сборка и запись файлов | `app/lib/build.php`, `app/lib/fs.php` |
| Какие поля есть в админке | `app/admin/schema.php` — добавить поле = одна строка |
| Сохранение, проверка значений | `app/admin/content.php`, операции — `app/admin/ops.php` |
| Интерфейс админки | `app/admin/ui/` (`admin.js`, `admin.css`) |
| Приём заявок | `app/lead.php`, отправка — `app/lead-deliver.php` |
| Порядок услуг, фоны первых экранов, фильтры портфолио, фото на главной | `data/structure.json` (правится в админке) |
| Цвета, вёрстка | `public/css/style.css` |

## Хранилище `storage/` (не в git, на сервер не заливается)

Пароль и секретное слово (`admin.json`), сессии, счётчик попыток входа, заявки (`leads/*.jsonl`), история правок (`revisions/`), корзина (`trash/`), настройки отправки заявок (`settings.json`). Сброс забытого пароля: `php app/bin/admin-setup.php <новый-пароль>` по SSH или удалить `storage/admin.json`.

## Публикация на хостинг (Beget)

Раскладка на сервере (папка сайта, например `~/stroygrad.ru`):

```
app/          ядро (из репозитория)
data/         контент — единственный источник правды
storage/      создаётся сама
public_html/  корень сайта: статика + собранные страницы
```

Ядро и данные лежат **вне** корня сайта; в `public_html` только две маленькие заглушки (`admin/index.php`, `lead.php`), `.htaccess` и `.user.ini`.

Первая установка:
1. `app/deploy.local.php` — доступ к FTP (пример `app/deploy.example.php`).
2. `app/config.server.php` — настройки сервера (пример `app/config.local.example.php`): адрес сайта, `public_dir`/`out_dir` = `public_html`, длинный случайный `deploy_key` (тот же — в `deploy.local.php`).
3. `php app/bin/deploy.php init <надёжный-пароль>` — зальёт код, данные и фото, положит настройки сервера, создаст вход в админку и напишет секретный адрес входа. SSH не нужен. На сервер с уже существующими данными не пойдёт.
4. Открыть главную и адрес входа, проверить, что всё работает.
5. В админке → Настройки: почта и Telegram для заявок, «Отправить проверочную заявку».
6. Когда на домене будет SSL — включить редирект на https в `public/.htaccess` и сделать `push`.
7. Выключить публикацию на GitHub Pages (иначе будет вторая, устаревшая копия сайта).

Дальше:
```bash
php app/bin/deploy.php push --dry   # что уедет
php app/bin/deploy.php push         # залить изменённый код и пересобрать сайт на сервере
php app/bin/deploy.php pull         # забрать правки клиента (data/ и фото) и закоммитить
```

Проверить на хостинге: версия PHP у веб-сервера ≥ 8.1, лимиты загрузки из `.user.ini` применились, `REMOTE_ADDR` — настоящий адрес посетителя, `mail()` отправляет письма, `api.telegram.org` доступен, адрес `/admin/...` доходит до `admin/index.php`.

## Форма заявок

Формы шлют заявку на `/lead.php` (адрес задан в `public/js/config.js`). Обработчик проверяет имя, телефон и согласие, отсекает ботов по скрытому полю `website`, **сначала записывает заявку в журнал** (видно в админке), отвечает посетителю и уже после этого отправляет письмо и сообщение в Telegram. Лимит — 30 заявок в час с одного адреса; сверх него заявка всё равно сохраняется, но уведомление не шлётся. Данные хранятся на сервере в РФ (152-ФЗ).

## Яндекс.Метрика

Номер счётчика — `public/js/config.js` → `METRIKA_ID`. Цели: `form_submit`, `phone_click`. После подключения обновите раздел «Файлы cookie» в `app/lib/pages.php` (функция `page_privacy`).

## Фото

Фото сайта — WebP: крупное 1280 px и превью 640 px (`public/img/<id>.webp`, `<id>-sm.webp`), описание — `data/photos.json`. Новые фото клиент загружает в админке. Тип `illustration` («не показывать в портфолио») — снимки только для страниц услуг.

Первые экраны — арт-коллажи из рекламных обложек клиента (`public/img/hero/`, без текста и QR-кодов). Пересоздать: `npm run art` (нужен `npm install` и папка клиента на диске). Их выбирают в админке, но загружать новые коллажи можно только через код.

## Палитра и смена темы

Все цвета заданы переменными в `:root` файла `public/css/style.css`; готовые варианты — в `public/css/themes/`. Смена темы = замена блока `:root` и `push`.

## SEO и разметка

Уникальные `title` / `description` на каждой странице (правятся в админке); один H1; ЧПУ; `sitemap.xml`, `robots.txt`; Open Graph и Twitter Card; JSON-LD: `GeneralContractor`/`LocalBusiness`, `Service` + `FAQPage` + `BreadcrumbList`. `npm run check` проверяет всё это на собранном `dist/`.

Подвал содержит студийную ссылку «Разработано в sitomika.ru» с UTM-метками (`utm_source=stroygrad-samara`).
