# СТРОЙГРАД — сайт строительной компании (Самара)

Многостраничный корпоративный сайт: главная, каталог из 14 услуг (у каждой своя страница), страница для УК и ТСЖ, портфолио, «О компании», контакты, политика конфиденциальности и согласие на обработку ПДн (152-ФЗ), страница 404.

**Стек:** статический генератор на Node.js (при сборке не нужны сторонние пакеты) → чистый HTML/CSS/JS. Никакой CMS и сборщиков: результат — папка `dist/`, которую можно положить на любой хостинг. Шрифт Manrope хранится на сайте (не грузится с чужих серверов).

## Быстрый старт

Нужен Node.js 20+.

```bash
npm run build:local     # собрать сайт в dist/ для проверки на своём компьютере
npm run dev             # открыть http://localhost:4173
npm run check           # проверка: ссылки, картинки, H1, title/description, микроразметка, sitemap
npm run build:draft     # то же, но с подсветкой неуточнённых данных {{УТОЧНИТЬ: …}}
```

## Где править тексты и данные

Весь контент лежит в `data/` — не в разметке. После правки выполните `npm run build` (или просто отправьте изменения в GitHub — сайт пересоберётся сам).

| Что менять | Файл |
|---|---|
| Телефоны, e-mail, Telegram/MAX, год основания, слоганы, **реквизиты** | `data/company.json` (единственный источник фактов — шапка, подвал, микроразметка и юр. страницы берут данные отсюда) |
| Тексты услуг (оффер, что входит, этапы, признаки, FAQ, сроки, гарантия, смежные услуги) | `data/services/<slug>.json` |
| Главная, «Для УК и ТСЖ», «О компании», «Контакты», «Портфолио» | `data/site.json` |
| Отзывы | `data/reviews.json` |
| Описания и категории фото | `scripts/photo-map.mjs` → `npm run images` |
| Цвета, шрифты, вёрстка | `public/css/style.css` (палитра «чёрный + золото» — переменные в `:root`) |
| Фон первого экрана каждой страницы | `data/services/<slug>.json` → `heroBg`; для остальных страниц — `HERO` в `build/build.mjs` |
| Шаблоны страниц | `build/build.mjs`, `build/lib.mjs` |

**Реквизиты в подвале и на странице «Контакты»:** заполните `requisites` в `data/company.json` (юрлицо, ИНН, ОГРН, юридический адрес, СРО) — блок появится сам. Пока поля `null`, блок скрыт. `npm run build:draft` показывает все места, где данных не хватает.

## Форма заявок

Заявки уходят на **один настраиваемый адрес** — константа `FORM_ENDPOINT` в файле `public/js/config.js`. Пересборка не нужна: правится прямо на сервере.

```js
FORM_ENDPOINT: "https://formspree.io/f/xxxxxxx",   // Formspree, Getform, свой скрипт, обработчик Telegram-бота
```

Форма отправляет `multipart/form-data` (`name`, `phone`, `service`, `message`, `subject`, `page`, `consent`, `want_portfolio`, `source_url`) и ждёт ответ 2xx. Скрытое поле `website` — ловушка для ботов (в норме пустое; ваш обработчик должен отклонять заявку, если оно заполнено). Валидация на стороне сервера обязательна: проверяйте `consent` и телефон — клиентские проверки обходятся.

Пока `FORM_ENDPOINT` пуст, форма **не притворяется рабочей**: после нажатия показывает телефоны, Telegram, MAX, e-mail и кнопку «Отправить письмом» с уже заполненным текстом.

> ⚠️ 152-ФЗ: персональные данные граждан РФ должны храниться в базах на территории РФ. Зарубежные сервисы форм (Formspree и т. п.) для боевого режима не подходят — используйте почтовый скрипт на российском хостинге или Telegram-бота на российском сервере. В политике конфиденциальности это утверждение уже записано.

## Яндекс.Метрика

Укажите номер счётчика в `public/js/config.js` → `METRIKA_ID: "12345678"`. Скрипт подключится сам. Цели для настройки в Метрике: `form_submit` (успешная отправка формы) и `phone_click` (клик по телефону). После подключения обновите раздел «Файлы cookie» в `build/build.mjs` (функция `privacyPage`) — сейчас там честно написано, что аналитики нет.

## Публикация

### GitHub Pages (уже настроено)
Файл `.github/workflows/deploy.yml` собирает, проверяет и публикует сайт при каждом пуше в ветку `main`. Адрес: `https://<аккаунт>.github.io/stroygrad-samara/`. Адрес и подпапка задаются в `site.config.json` (`siteUrl`, `basePath`) — они попадают в canonical, sitemap и Open Graph.

### Свой домен / российский хостинг
1. В `site.config.json` поставьте `"siteUrl": "https://ваш-домен.ru"` и `"basePath": ""`.
2. `npm run build` → загрузите содержимое папки `dist/` в корень сайта на хостинге (по FTP или через панель).
3. Для GitHub Pages со своим доменом: добавьте файл `public/CNAME` с доменом и переменную репозитория `SITE_BASE` (пустая).
4. После запуска отправьте `https://ваш-домен.ru/sitemap.xml` в Яндекс.Вебмастер и Google Search Console.

Страница 404: на GitHub Pages используется автоматически; на обычном хостинге настройте `ErrorDocument 404 /404.html` (Apache) или `error_page 404 /404.html;` (nginx).

## Фото

Исходники клиента остаются вне репозитория (папка на диске D). В репозитории — только оптимизированные WebP: крупное 1280 px и превью 640 px, `loading="lazy"`, `width/height`, `srcset`. Добавить или заменить фото:

1. Положите файл в папку клиента и добавьте строку в `scripts/photo-map.mjs` (индекс, описание `alt`, тип `object` / `collage` / `illustration`).
2. `npm run images` — пересоздаст WebP и `data/photos.json` (нужен `npm install`, используется sharp).
3. При необходимости укажите фото в `gallery` / `hero` услуги в `data/services/*.json`.

### Первые экраны и обложки клиента

На всех страницах первый экран — полноэкранный фон из рекламных обложек клиента («Фото обложки»), текст поверх, чёрно-золотая стилистика обложек. Фрагменты вырезаны **без текста и без QR-кодов** и лежат в `public/img/hero/` (одиночные арты, диагональные коллажи, облегчённые `-m.webp` для телефонов). Пересоздать: `npm run art` (нужен `npm install` и папка клиента на диске). Тексты обложек (девизы, «Почему выбирают нас?», списки работ и техники) перенесены в `data/`.

Тип `illustration` — снимки, которые, вероятно, не с объектов компании: они показываются только на странице услуги и **не попадают в портфолио**.

## Структура проекта

```
data/            контент (JSON)
build/           генератор (build.mjs — страницы, lib.mjs — шапка/подвал/формы, icons.mjs — иконки)
public/          статика: css, js, шрифты, фото, favicon, og.jpg
scripts/         оптимизация фото, проверка, локальный сервер
QUESTIONS_FOR_CLIENT.md   вопросы клиенту
CONTENT_GAPS.md           чего не хватает из контента
```

## SEO и разметка

Уникальные `title` / `description` на каждой странице; один H1; ЧПУ; `sitemap.xml`, `robots.txt`; Open Graph и Twitter Card; JSON-LD: `GeneralContractor`/`LocalBusiness` (главная, «О компании», контакты), `Service` + `FAQPage` + `BreadcrumbList` (страницы услуг). `npm run check` проверяет всё это автоматически.

Формат изображений — WebP (поддерживается всеми браузерами с 2020 года), запасной формат не предусмотрен.

Подвал содержит студийную ссылку «Разработано в sitomika.ru» с UTM-метками (`utm_source=stroygrad-samara`).
